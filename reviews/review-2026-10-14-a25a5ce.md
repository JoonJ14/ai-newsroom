## Context

GitHub Codex left one P2 comment on PR #7. Anthropic articles were filtered on their
listing date (midnight UTC) before the article page was read for the exact
`article:published_time`. An article from seven days ago could be dropped while its
real time was still inside the window. The fix (`enrichRecent`): use a 2-day-wider
window to pick candidates, enrich them, then apply the strict 7-day filter to the
exact times. That fix started this review. Tier 3 then reviewed the whole branch.

### What was fixed, by area

- **Storage.**
  - If the stored-metadata read fails, or hits PostgREST's 1,000-row cap, the
    upsert only inserts new rows instead of erasing coverage.
  - `postgrestInList` quotes and escapes every URL. supabase-js's `.in()` doesn't
    escape `"` or `\`.
  - A failed batch fails the run (exit code 1). The backstop calls
    `process.exit()`, which keeps that exit code.
  - `collect.yml` has a `concurrency: collect` group.
- **Collection.**
  - `readBody`: a 10 MB cap, and the stream is cancelled when exceeded.
  - A 5-minute budget, after which remaining sources are skipped.
  - The 7-day filter runs on exact times (the GitHub comment).
- **Text.**
  - Control characters and lone surrogates are dropped.
  - Every item's text is decoded exactly once: `htmlToText` no longer decodes, and
    cheerio text passes `decoded`.
  - HN summaries are cut after decoding.
  - `cutText` and `firstSentence` never split a surrogate pair.
  - Percent-encoded `utm_` keys are stripped, in either case.
- **Changelog identity.**
  - URLs are `?day=…&entry=…#…`.
  - Bullets that collide on their first eight words get a hash of their text, not
    a position number.
- **Dedup**, rebuilt as story clusters:
  - Copies of one `(url, source)` row are merged first, so an upsert batch never
    holds a row twice.
  - Then every URL match is made, then title matches.
  - Titles merge copies from different sources only.
  - A story never holds two different URLs from one source.
  - The kept row carries the story's biggest HN thread.
  - Fragments are ignored except app routes.
  - On 885 stored rows, the only difference from the committed version is 14
    InfoQ pairs that exist only across runs.
- **Digest delivery** (rendering unchanged):
  - Telegram is plain text, with a word joiner after `@`.
  - Discord: `allowed_mentions: { parse: [] }`, and markup is escaped on title lines.
  - Slack: `mrkdwn: false`, with `& < >` escaped.

### Not fixed, with reasons

- **Cross-run duplicate rows** (round 1). Identity is `(url, source)` by design
  (CLAUDE.md). Dedup is per run, as before.
- **A local `npm run collect` overlapping an Actions run** (round 3). Documented in
  CLAUDE.md. Actions runs are serialized.
- **Editing a colliding changelog bullet changes its hash identity** (round 3). This is
  documented. It needs two bullets on one day sharing eight opening words.
- **The workflow `GITHUB_TOKEN` and other public repos** (round 6). False positive: an
  installation token reads public resources of any repository (`actions/checkout` of
  another public repo uses the same default token). The first Actions run confirms it.
- **Re-running dedup on its own output** (round 9). Not a production path. The input
  contract is in the doc comment.
- **RSS text decoded a second time** (round 9). Intended: The Verge's feed encodes
  entities twice. The reason is in a comment in `index.ts`.
